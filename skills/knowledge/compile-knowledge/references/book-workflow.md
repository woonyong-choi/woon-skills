# 책 편입 계약

책 원문을 Wiki에 편입할 때는 본문을 쓰기 전에 판본이 일치하는 목차를 먼저 고정한다.

책 편입은 [책 4단계 품질 계약](repo://skills/standards/learning-content-quality.md#book-four-phase-workflow)을 따르는 단방향 상태 전이다. 네 단계는 별도 번역본·개념판·학습판 페이지를 만드는 절차가 아니라 같은 canonical tree의 reader unit을 증분 갱신하는 절차다. 미래 promotion payload는 `workflow_phase`, `translation_required`와 unit별 `reader_language`, `source_prose_verified`를 명시하며, 이전 phase나 이미 검증한 source structure·element·delivery를 되돌리거나 줄이지 않는다.

## 독자 화면과 개인 각주

모든 책의 기존·신규 reader에 같은 표시 계약을 적용한다. 실제 적용 순서는 사용자가 정한 책·장 범위를 따르며, 이미 검증한 다른 장을 다시 생성하지 않는다.

- H1 바로 아래에 같은 판본·reader unit의 실제 한국어·English 전환 링크를 둔다. 존재하는 상대 언어 본문만 연결하고, 영문이 없는 한국어 원서는 영문이나 빈 링크를 만들지 않는다. 언어별 화면을 별도 Wiki 정체성으로 복제하지 않는다.
- 본문은 책 원문 또는 번역의 문장·그림·표·code를 보존한다. 사용자의 질문·이해·추가 예제·사이드 프로젝트 통찰은 관련 본문 단어에 각주 번호로 연결하고, 본문 하단의 `---` 아래 개인 각주에만 둔다. 원문 자체의 각주와 개인 각주는 서로 다른 stable ID를 사용한다. 보강이 없으면 빈 개인 각주·구분선·가짜 질문을 만들지 않는다.
- 각주는 별도 source·claim에 실제 대화 provenance와 시점을 보존한다. 같은 보강은 안정 ID로 증분 병합하고 반복 실행으로 복제하지 않는다. 원전 사실·현재 근거·사용자 해석을 구분하며, 원문의 문장·그림·표·code를 개인 설명으로 교체하지 않는다. 일반화한 개념은 기존 개념 Wiki를 연결하고 본문을 중복 복사하지 않는다.
- 독자 각주는 편집·작업 보고 접두어나 “수정했다·보완했다” 같은 이력 문체 없이 설명 자체로 쓴다. 순수 조판 처리 이력은 내부 변경 근거에만 보존한다. 표현을 정리한다는 이유로 설명을 일괄 단축하지 않는다. 실제 대화로 확인한 막힌 지점과 당시 생각, 혼동한 이유, 실행 순서·값의 변화·비교 조건·적용 경계를 필요한 만큼 풀어 쓴다. 사용자가 직접 드러낸 어려움과 작성자가 추론한 어려움을 구분하며, 설명을 제공하거나 예제가 통과한 사실을 사용자 이해 완료로 기록하지 않는다. 후속 문답에 재사용할 수 있도록 기존 대화·학습 예제와 연결하되 별도 문제은행·진도 DB·반복 보고서를 만들지 않는다.
- 기존 개인 각주의 문체 수정·불필요한 조판 각주 제거는 stable ID를 명시한 scoped transaction으로 처리한다. immutable source·claim은 보존하고 수정한 설명은 새 claim으로 연결한다. 남긴 각주의 anchor·상대 순서와 원문·번역의 의미·코드·실행 근거를 유지한다. 코드가 포함된 각주는 prose-only 수정 경로로 바꾸거나 삭제하지 않는다.
- 언어 링크와 개인 각주는 source payload와 분리된 reader presentation이다. 각주 번호는 렌더링할 때만 삽입하고, 원본 PDF·EPUB·HTML·image와 고정한 source/translation payload·coverage hash를 표시 변경 때문에 수정하지 않는다. archive Markdown의 H1·언어 링크와 `archived_body_sha256`이 고정하는 본문 범위도 구분한다. 표시 입력·출력 revision/hash는 독립 갱신할 수 있으며 이를 원문 변경으로 오판해 막지 않는다.
- 번역 표현이나 이미지 표시를 고쳐 달라는 요청은 지정한 부분만 수정한다. 과거 번역 본문에 편집 보고 문장이 섞여 있으면 현재 source record hash·정확한 보고 문장·제거 후 body hash를 명시한 새 독자 revision으로만 분리한다. 원래 source·claim은 이력으로 보존하고, coverage span은 같은 보고 문장을 제외한 값으로만 다시 고정한다. source element·owner·원문 의미 단위·코드와 나머지 본문 변경은 허용하지 않는다. 원본 payload는 보존하고 해당 번역·표시 revision과 영향을 받은 delivery 근거만 갱신한다. 원본 실행 예제와 개인 보충 실행 예제의 번호·code hash·receipt는 각각 검증한다.
- 공용 Vault·catalog의 현재 writer 한 명이 적용하고, 번역 담당은 격리된 번역 입력을 제공한다. 표시 기능이 현재 compiler/adapter에서 지원되지 않으면 원문이나 generated Markdown을 임시 수정하지 않고 Core 담당과 정확한 renderer·validation·transaction 범위를 합의해 지원을 보완한다. 화면 확인과 실행 검증은 별도 근거로 보고한다.

## 편입과 검증

- 원서의 판권·ISBN·판·전체 장·절 번호를 원문 PDF 또는 출판사 페이지에서 확인한다.
- 같은 판본의 공식 한국어판이 있으면 출판사나 서점의 전체 목차를 찾아 장·절 번호와 번역 용어를 대조한다. 검색 결과 제목만 보고 한국어판이 있다고 가정하지 않는다.
- 한국어판 목차가 없을 때만 번호와 계층을 유지한 채 자연스러운 한국어로 번역한다. 번역 때문에 절을 병합·분할·재번호화하지 않는다.
- 책·장·reader의 화면 계층은 [책 탐색 정본](repo://skills/skills/knowledge/knowledge-navigation/SKILL.md)과 사용자의 현재 구조 요청을 따른다. 장 page를 필수 경유지로 강제하지 않으며, 평탄화가 승인되면 책 첫 목차에 비링크 장·절 키워드와 실제 본문 링크를 펼친다. 원문 장·절·항의 번호와 순서, 각 reader unit의 exact-once 본문 소유권을 보존한다. `부`, `장`, `절`, `항`, `부록`, `요약`은 표준 한국어 구조 용어로 사용하고 원문 용어는 source metadata·alias·필요한 최초 병기에 둔다.
- 현재 승인된 책·장·reader 구조는 유효한 기준이며, 별도 migration 요청 없이 퇴역 대상으로 취급하지 않는다. 한 책 안에서 두 형태를 조용히 섞지 않고 coverage manifest가 장별 layout을 명시해야 한다. source-owning 장 페이지를 퇴역해 여러 절 페이지로 나눌 때는 full coverage replacement에서 `source_elements`를 그대로 유지하고 `source_element_assignments.owner_id`만 선언한 successor들로 exact-once 이동한 `retirement_content_relocations`를 preflight한다. 원문·code·image delivery evidence가 바뀌거나 한 successor라도 원문 element를 받지 못하면 중단한다. source-free `toc-indexed` 장 wrapper는 content relocation을 주장하지 않고 exact structure/navigation replacement로만 퇴역한다.
- 표지 뒤의 저자 서문·저자 소개·역자 서문과 본문 뒤의 부록·참고문헌·찾아보기도 source structure inventory에 원문 순서대로 넣는다. 의미 있는 학습 본문은 reader에 보존하되, 단순 절 안내문은 첫 실제 본문에 중복 없이 합칠 수 있다. 사용자가 비학습 앞부분의 분리 페이지 제거를 요청하면 표지·판권·저자 소개 등은 원본 PDF·자산·판본 식별 정보와 고정 locator로 보존하고 해당 reader wrapper를 퇴역한다. 비학습 구조 요소는 inventory에서 누락시키지 않고 `metadata-only` 위치를 명시한다. 본문이 있는 부록과 code는 일반 학습 본문과 같은 보존·runnable 계약을 적용한다.
- 목차 근거 URL·확인일·판본 경계를 source 또는 page provenance에 남긴다. 원서와 한국어판의 판본이나 구조가 다르면 원서 구조를 정본으로 삼고 번역 용어만 참고했다고 명시한다.
- `source-landed`에서는 원문 언어와 순서를 보존한 독자 본문을 같은 reader unit에 편입하고 `source_prose_verified: true`를 근거로 고정한다. 이 단계는 번역 품질을 판정하지 않으므로 `korean_prose_reviewed`를 요구하지 않는다. `translated`에서는 같은 reader unit을 핵심 정보와 논리 순서를 빠뜨리지 않는 자연스러운 한국어로 갱신하고 `reader_language: ko`, `korean_prose_reviewed: true`를 요구한다. 한국어 원서는 `translation_required: false`로 두고 source 본문 검토를 통과하면 번역은 no-op이다.
- 원문의 모든 의미 단위를 `claim`, `example`, `caution`, `figure`, `code` source element로 분해한다. **reader unit**은 기본 형태의 N.M 절 페이지와 terminal N.M.K 하위 절 페이지이며, migration 전의 장 reader 형태에서는 검증된 장 H2 span도 reader unit으로 인정한다. 한 element는 원문 문단·표·문제·그림·code block처럼 독립 의미를 보존하는 최소 단위이며 OCR line, 임의 ordinal, 장별 총개수는 element가 아니다. 각 element는 종류·semantic unit·정확한 source locator·원문 span 또는 image bytes의 SHA-256에서 계산한 stable ID를 갖고 정확히 하나의 reader unit에 배정한다. non-code element는 독자 본문에 정확히 한 번 존재하는 delivery span과 그 SHA-256을 고정하며, 같은 reader unit·종류·span을 여러 element가 재사용할 수 없다. figure는 Mermaid block·local image·prose span 중 실제 독자가 보는 표현의 hash를 검증한다. prose로 전달하는 figure는 `그림 N의 제목` 같은 짧은 label 반복이 아니라 입력·변환·출력, 방향, 비교 또는 원인·결과 중 그 그림이 답하는 실제 관계를 설명해야 한다. unit별 claim·example·caution·figure·code 수는 assignment에서 파생되어야 하며 count-only coverage를 허용하지 않는다.
- `claim semantic unit 5`, `unnumbered source code segment` 같은 내부 inventory·ordinal 문장과 `한다이다`, `줄인다을` 같은 자동 결합 흔적은 독자 본문에 쓰지 않는다. delivery span은 자연스러운 한국어 문장 자체여야 하며, 내부 원문 대조 정보는 manifest와 provenance가 소유한다.
- 원문의 모든 code 예시는 위 semantic inventory에 exact-once 배정하고 verbatim으로 보존한다. 원문 그대로 독립 실행 가능한 예제만 해당 언어의 고유한 `run-*` block 하나로 만들고 source·compile·run·output을 receipt에서 검증한다. 서로 다른 원문 code/example element를 하나의 대표 실행 block에 공동 배정하지 않는다. fragment, 외부 dependency, 의도적 compile error, placeholder처럼 원문을 바꾸지 않고는 독립 실행할 수 없는 예제는 원문 static fence로 보존하고 manifest에 `runnable_required: false`, `fragment|dependency|intentional-error|placeholder` 이유 code, 정확한 source locator·hash, static body hash와 고정 evidence를 남긴다. 원문 listing을 설명 주석만 있는 fence, 출력 상수를 그대로 적은 block, synthetic wrapper·harness나 대체 code로 바꾸지 않는다. 원문 밖 실행 전 예측·변형 지시·Reset 안내·완료 기준·검증 상태 prose도 reader body에 추가하지 않는다. 독립 실행 가능한 원문 code가 미검증이거나 static 예외의 source·body·evidence가 고정되지 않으면 그 범위를 `code-verified`·`reviewed` 또는 완료로 판정하지 않는다.
- 하나의 원문 code element를 여러 정적 fence로 나눠 표시할 때만 `static_parts`를 사용한다. 기존 `element_id`·`owner_id`·source identity·예외 사유·`original_test_evidence`는 유지하고, 단일 `static_language`·`static_block_index` 대신 최소 두 part의 `language`, 최종 reader 전체에서 같은 언어의 1-based `block_index`, 정확한 `body_sha256`을 파일 순서대로 기록한다. 각 part와 이어 붙인 payload의 `static_body_sha256`이 모두 일치해야 하며, 다른 element가 어느 part도 재사용할 수 없다. `source_payload_evidence`에는 private Vault 상대 `relative_path`, 해당 source-blocks JSON의 `sha256`, 유일한 `block_id`, `canonical_locator`, `extracted_locator`를 고정한다. 기록의 원본 HTML hash는 기존 source hash와, `english_md` hash와 fence payload는 표시한 전체 code와 일치해야 한다. locator는 같거나 같은 원본 member 안의 `block-N` ↔ `dom-child-N` 대응을 명시해야 한다. 첫 fence만 검사하거나 source element를 새로 나눠 통과시키지 않으며, 이 표시 변경은 새 실행 증거가 아니다.
- 원문 제목이 compiler H1이나 실제 조상의 목차 H2에서 표시되면 `delivery: reader-heading`으로 그 위치를 고정한다. 기존 leaf `owner_id`는 유지하고 `heading_page_id`, 정확한 `heading`, `heading_sha256`, `source_mapping_evidence`를 기록한다. 원문이 실제 HTML heading인지, 같은 scope의 실제 부모 계층에 있는지, H1이 페이지 제목과 같은지, H2가 해당 leaf를 포함하는 `navigation_groups`의 label인지, 원래 절 번호와 표시 위치가 정확히 하나인지 검증한다. 제목을 임의의 본문 문장으로 대체하거나 source owner를 부모로 바꾸지 않는다.
- 기존 Markdown hash로 식별된 하나의 원문 `<pre>`를 언어별 여러 정적 fence로 표시할 때는 `static_parts`와 `source_payload_evidence: {source_mapping_evidence: {relative_path, sha256}}`를 사용한다. 기존 identity·owner를 원본 DOM에 대조하고, 출력 fence를 원문 순서로 이은 코드가 해당 `<pre>`와 일치해야 한다. CRLF/LF와 마지막 개행 한 개만 정규화하며, 코드·오류 출력·주석의 누락·변경이나 원문 ID 분할은 허용하지 않는다.
- 원문 자체에 같은 문단·코드 설명이 반복되면 `delivery: reader-span-occurrence`에 `delivery_span`, `delivery_span_sha256`, 1-based `span_occurrence`, `source_mapping_evidence`를 기록한다. 같은 owner·kind·원문 hash를 가진 source element 전체와 독자 본문의 동일 문구 개수가 같고, 모든 element가 원문 DOM 순서대로 서로 다른 occurrence에 배정되어야 한다. 앞뒤의 다른 의미 단위를 span에 합치거나 번역 문구를 억지로 바꿔 중복 검사를 피하지 않는다.
- 위 `source_mapping_evidence`의 `relative_path`·`sha256`은 private JSON을 가리킨다. JSON은 원본 HTML의 `document_locator`·private `document_path`·`document_sha256`과 element별 `records`를 고정한다. 각 record는 `element_id`, `owner_id`, `source_locator`, 기존 source hash와 정확히 일치하는 `legacy_source_markdown`, `dom_child_index`, 선택적인 자식 번호 `subindex`, 정확한 원본 DOM 범위의 `source_excerpt_sha256`을 포함한다. 기계 경로·symlink를 source identity로 쓰지 않으며, legacy Markdown hash를 새 HTML hash로 덮어쓰지 않는다. code는 원문 `<pre>`, 일반 문구는 실제 원문 text와 대조한다. 출력용 번호·공백과 출판사가 명시한 줄 연결 표시 이외의 원문 내용 변경은 허용하지 않는다.
- `runnable_support_corrections`의 `static-exception → supported`는 원문 그대로인 독립 프로그램이 실제 성공 실행된 경우에만 허용한다. 기존 source identity·순서·leaf owner는 유지한다. correction evidence의 해당 result에는 기존 compile/run 종료값·출력과 함께 `execution_kind: source-standalone`, `source_element_id`, `source_mapping_evidence`, private `executed_source_path`·`executed_source_sha256`, private `original_result_path`·`original_result_sha256`, 실제 사용한 파일과 hash의 `runtime_dependencies`를 고정한다. 코드 파일·원본 실행 기록·최종 run fence payload가 모두 일치해야 한다. 승격한 run-block assignment에도 `execution_kind: source-standalone`을 유지하고 correction evidence의 정확한 locator·hash·source_element_id·result를 결합한다. 원래 실행 기록에 선언된 의존성은 전부 대조한다. path가 있으면 path와 hash가 같아야 하며, hash만 남은 기록은 동일 hash의 실제 로컬 파일을 확인하되 과거 path까지 확인한 것으로 표현하지 않는다. wrapper·조합 예제·의도적 오류·비정상 종료는 승격하지 않으며, 성공을 얻기 위해 무작위 예제를 재실행하지 않는다. 기존 `supported → static-exception`의 검토 조건도 유지한다.
- 책마다 source coverage manifest를 유지한다. manifest는 판본·ISBN·원문 hash, 확인한 한국어 목차 근거, 예상 부·장·절·세부 절 ID와 source locator, semantic inventory extraction method·policy hash, 모든 source element와 exact reader delivery를 기록한다. 상태는 `toc-only`, `drafted`, `source-covered`, `code-verified`, `reviewed`만 사용하고, 예상 reader unit이 없거나 locator·중요 항목 대조가 남으면 책을 완료로 판정하지 않는다. 빈 shell, 제목만 있는 페이지, count-only manifest, 원문 hash가 없는 element, 본문에 없는 delivery evidence는 coverage로 세지 않는다. promotion payload와 coverage manifest schema가 바뀌면 과거 payload를 변환해 재검토하며 버전 숫자나 hash만 바꿔 재사용하지 않는다.
- 외부 폴더에 여러 자료가 섞여 있으면 source catalog의 모든 file locator를 정확히 하나의 book·extract·course·standard·paper·tutorial bundle에 배정한 `catalog/book-intake/<source>.json`을 먼저 만들고 `woon knowledge book-intake-audit`을 통과한다. file count를 책 권수로 보고하지 않으며, 미배정·중복 배정·권리 미확인 상용 원문의 본문 승격을 허용하지 않는다.
- 원문 기반 설명과 학습 대화 보강을 서로 다른 provenance로 추적한다. 원문층은 새 대화 때문에 삭제·축약·대체하지 않는다. `understanding-enriched`에서만 대화에서 확인된 오개념·추가 질문·실행 결과를 위 개인 각주 계약에 따라 해당 reader unit의 별도 보강 claim으로 연결하고 `source_session_ids`와 시점을 남긴다. 일일 대화 취합도 같은 identity·optimistic revision·중복 병합 계약을 따르며, 새 보강은 기존 source·translation coverage hash를 바꾸거나 감소시키면 실패한다. 이 단계는 계속 성장하는 상태이므로 전권 완료의 global blocker가 아니다.
- `source-landed`와 `translated` reader body에는 원문에 없는 인출·전이 문제, 예측·변형·Reset 안내, `직접 확인하기`, `자료를 닫고 답하기`, `이전과 다음`, `완료 기준`, `검증 상태` section을 만들지 않는다. 선형 이동의 순서는 정본 Map의 `navigation_groups`와 `sequence`가 소유한다. 책 root에서 `reader_leaf_navigation: true`로 표시를 선택하면 compiler는 실제 본문이 있는 리프 순서에서 하단의 이전 본문·책 목차·다음 본문 링크를 파생한다. 장 목차·원문 archive·다른 책은 본문 사이의 이동 대상으로 넣지 않으며, 이 표시 때문에 source payload나 학습 관계인 `prerequisites`·`next_concepts`를 바꾸지 않는다. `understanding-enriched`에서도 실제 대화·실행 근거는 관련 단어에 연결한 개인 각주에 보강하고 위 workflow section을 템플릿처럼 반복 생성하지 않는다.
- 원문의 권리나 출처가 불명확하거나 AI 처리 금지가 명시돼 있으면 fail closed한다. 공개 출판사 목차로 구조만 검증할 수는 있지만, 본문을 추출·번역·claim으로 승격하지 않고 `toc-only` 또는 Review로 남긴다.
- 사용자가 구매·소유한 원본을 직접 제공하고 이 private Vault 안에서의 처리를 명시적으로 승인한 경우에만 별도 `user-authorized-private` 권리 상태를 사용할 수 있다. 이 상태는 byte-pinned `private/local-only` source archive에서 같은 범위의 `source-landed` 책 정본을 복구·편입하는 권한일 뿐이다. intake에는 `user-purchased-copy` ownership basis, source archive path·SHA-256, 권리 고지 locator·SHA-256, 사용자 승인 receipt locator·SHA-256·승인일과 `source-landed-private-local-only` scope를 고정한다. `external-transmission-prohibited`, `model-training-prohibited`, `publication-prohibited`, `redistribution-prohibited` 제한은 항상 함께 유지하며 공개·배포·외부 전송·모델 훈련을 승인한 것으로 확대 해석하지 않는다.
- `processing-prohibited`로 demotion된 책을 다시 편입할 때는 일반 `book-promote`로 우회하지 않고 `book-rights-restore`의 apply:false preflight와 단일 원자 적용을 사용한다. 현재 blocked intake hash와 격리 manifest·entry bytes, immutable archive hash, 승인 receipt를 모두 다시 대조한 뒤 intake를 `user-authorized-private`로 바꾸고 책 정본과 coverage를 함께 복구한다. 어느 단계든 실패하면 intake·compiler input/output·coverage·asset·index를 rollback하며, 격리본과 구매 원본은 삭제하거나 덮어쓰지 않는다.
- book reader unit과 일반 개념 문서는 서로 다른 identity다. book reader unit은 “이 판본의 이 절이 무엇을 어떤 순서·예제로 설명하는가”를, 개념 문서는 “여러 근거와 현재 기술 기준에서 이 개념을 어떻게 이해하는가”를 소유한다. 책에 없는 질문·추가 자료·새 버전·실험은 개념 문서를 성장시키며 책 원문층에 소급 삽입하지 않는다. 책의 독해를 위해 필요한 보강만 해당 reader unit의 개인 각주에 두고, 일반화된 설명은 개념 canonical에 한 번만 남긴 뒤 양쪽을 검증된 wikilink와 relation으로 연결한다.
- 책 판본과 현재 개념 근거가 다르면 어느 한쪽을 덮어쓰지 않는다. 책에는 출간 판본의 설명과 현재 차이를, 개념에는 현재 근거와 적용 버전을 남기고 서로 연결한다. 같은 문단·예제·결론을 양쪽에 복제하거나 같은 parent tree로 합치지 않는다.
- 책 본문 편입과 개념 Wiki 확장은 서로 다른 phase다. `source-landed`와 필요한 `translated`가 책 전체에서 끝난 뒤에만 `concept-linked`를 실행한다. 새로 생긴 reader body를 재생성하지 않고 현재 book content hash를 기준으로 기존 개념과 관계만 증분 대조·연결한다. 관계 evidence에는 대상 canonical ID, 현재 책 본문 hash, 판단 근거를 남긴다.
- 책은 한 번에 한 장씩 처리한다. 최초 1회 고정한 판본·목차·source structure·source element inventory를 재사용하고, hash가 바뀌지 않은 reader unit·번역·실행 receipt·quality review를 다시 생성하거나 다시 평가하지 않는다. `source-landed`의 각 장은 `목차 범위 고정 → 원문 언어·순서로 source element exact-once delivery → code exact-one runnable 검증 → apply:false preflight → merge-scope 원자 적용 → scoped audit`로 끝낸다. 번역이 필요하면 같은 reader unit을 `translated` phase에서 한국어로 갱신하되 immutable source inventory와 provenance를 그대로 유지한다. 다른 장이 legacy·pending이면 전권 manifest를 교체하지 않고 `catalog/book-coverage-scopes/<book>/<chapter>.json` fragment를 사용하며, 검증된 장·phase만 완료로 보고한다.
- 여러 agent가 책을 병렬 생성하더라도 공용 Vault writer는 하나뿐이다. agent는 격리된 hash-pinned 산출물만 만들고, 현재 writer가 검증·적용 중인 동안 같은 책의 payload·catalog·generated Markdown을 다시 만들거나 덮어쓰지 않는다. 실패한 preflight나 rollback은 원인을 고친 같은 장만 재생성하며 전권 초안과 다른 완료 장을 재작업하지 않는다.
- AI·compiler·agent를 위한 작성 절차, page ownership, completion gate, navigation 설명은 reader-facing 책 본문에 넣지 않는다. 이런 계약은 skill·source coverage manifest·receipt·학습 프로젝트가 소유한다. 독자에게 필요한 판본·page locator·현재 공식 문서 근거만 reader unit 하단의 짧은 provenance로 남긴다.
