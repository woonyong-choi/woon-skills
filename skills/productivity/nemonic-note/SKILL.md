# Nemonic Note

사용자가 붙여 두고 다시 볼 핵심을 Nemonic의 편집 가능한 짧은 메모로 만든다. 초보자가 한 장만 읽어도 개념, 설정 위치, 동작 원인과 예시를 이해하게 한다.

## 작성

- 한 장마다 개념부터 자연스럽게 설명한 뒤 `어디에 설정하는가 → 설정하면 무엇이 바뀌는가 → 왜 오류가 나는가 → 어떻게 고치는가` 순서로 이어 쓴다. `[설정]`, `[사용 코드]`, `[이유]` 같은 기계적인 표지는 쓰지 않는다.
- 설정은 해당 설정 파일의 실제 문법으로, code는 해당 언어의 실제 문법으로 쓴다. 설명은 code 위나 아래의 완결된 한글 문장으로 배치한다. 실제 source에 들어갈 comment가 아니면 설명 앞에 `//`를 붙이지 않는다.
- 한 장만 떼어 보아도 이해되게 필요한 원인을 남기고, 중복 정의·당연한 결론·장식용 문구부터 줄인다. 단순히 결론만 적지 말고 예를 들어 "컴파일 오류"라면 생략된 접근 지시어와 반환 타입처럼 직접 원인을 쓴다.
- 흰 배경, 검정 글자를 사용한다. ASCII code는 `JetBrains Mono`, 한글은 Gothic fallback을 사용하고, 10pt를 시작점으로 하되 한 장에 필요한 설명이 부족하면 9pt까지 줄인다.
- Nemonic 편집기의 기본 안쪽 여백을 그대로 쓰고 별도 큰 여백을 추가하지 않는다. 가로 폭을 적극적으로 사용하며, 들여쓰기는 실제 code 구조에 필요한 최대 2단계만 둔다. 내용은 종이 높이의 약 70~85%를 채우되 잘림이나 자동 스크롤이 없어야 한다.

## 출력

- 기본 경로는 현재 Nemonic 편집기에 요청한 장수만 직접 작성하는 것이다. 작업 전 열린 초안 수를 확인하고, 새 창은 부족한 수만 만든다. 중복 창을 만들지 않는다.
- 영구 시작점은 사용자의 기존 `Code-Block-10pt.nemo` 하나다. 사용자가 파일 보존을 원하면 개별 학습 메모를 편집 가능한 `.nemo`로 임시 생성한다. PDF는 사용자가 PDF 또는 CUPS 직접 출력을 명시한 경우에만 만든다.
- 각 메모를 화면에서 다시 읽어 문장 잘림, 강제 줄바꿈, 깨진 한글, 과도한 빈 공간과 요청 장수 일치를 확인한다.
- 현재 MIP-201 CUPS 경로의 두 번의 실물 확인 결과, 정상 PDF는 90도 돌아갔고 첫 보정본은 180도 뒤집혔다. 같은 queue·driver에서는 첫 보정본의 선회전 방향을 180도 반대로 적용한다. 장치나 driver가 바뀌면 이 보정을 재사용하지 않고 다시 확인한다.
- Nemonic 앱 출력은 앱의 인쇄 버튼을 사용한다. CUPS 직접 출력 요청이면 먼저 `lpstat`, queue의 80x80 media option, pending job을 확인한다. 사용자가 출력까지 요청한 경우에만 한 번 전송하고 job ID와 queue 완료를 재조회한다.
- queue 완료는 데이터 전달 근거일 뿐 실제 종이 배출·방향·잘림의 증거가 아니다. 사용자의 실물 확인 전에는 성공이라 하지 않고 재출력하지 않는다.

## 수명과 정본

- 정상 실물 출력을 사용자가 확인하면 개별 `.nemo`, PDF와 render 임시물을 삭제한다. 실패하거나 미확인이면 교정이 끝날 때까지 보존한다. 기본 `Code-Block-10pt.nemo`는 삭제하지 않는다.
- 출력 메모를 자동 archive하거나 Wiki에 복사하지 않는다. 사용자가 명시적으로 Wiki 정리를 요청했을 때만 해당 owner skill로 기존 절의 `내 이해·보충`에 병합한다.
